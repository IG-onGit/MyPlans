Features

A planner that respects your files

Everything MyPlans shows comes from YAML you can read, edit and commit.

  • Plain YAML, your files

    Plans live in .yml / .yaml files in your workspace. Hand-editable, diffable and yours to keep.

  • Check = comment out

    Ticking a step comments its line out in the file. Un-ticking restores the original line.

  • ASAP flags

    Mark urgent steps with an [ASAP] tag. A pulsing dot bubbles up to the task, topic and category.

  • Progress at a glance

    Global and per-category progress bars, plus counts of categories, topics, tasks, done and left.

  • Keyboard first

    Navigate with the arrow keys, toggle with Enter, and jump into the panel with Ctrl+Shift+M.

  • One-click Deploy

    Stage, commit with a timestamped message and push, straight from the panel.

How it works

From empty folder to done list in three steps

Categories are folders, topics are YAML files, tasks are keys, steps are list items.

  1. Open a workspace

    Open a folder in VS Code and click the MyPlans icon in the Activity Bar.

  2. Build your tree

    Add a category, then a topic (a YAML file), then tasks and steps, using the + buttons.

  3. Check things off

    Tick steps as you finish them. Progress updates live, and Deploy pushes your plan to Git.

Usage

Done means commented out

Ticking a step comments out its line. Un-ticking brings it back. Your file always shows the truth.

  • Simple Task Name: plus - step format
  • Works with LF, CRLF, tabs and 2 or 4 space indents
  • Edit in the panel or directly in the file

FAQ

Questions, answered

Is MyPlans free?

Yes. MyPlans is open source under the MIT License, so you can use, modify and share it for free.

Where is my data stored?

In plain .yml and .yaml files inside your workspace. You can edit them by hand, and MyPlans re-reads them whenever they change on disk.

Do I need Git?

Only for the Deploy button, which needs the workspace to be a Git repository with a remote and push access. Everything else works without Git.

Can I use my existing YAML files?

If they follow the Task Name: followed by - step lines format and sit inside a folder at the top level of your workspace. Arbitrary YAML schemas and files in the workspace root are not scanned.

Which VS Code version do I need?

VS Code 1.85 or later.
